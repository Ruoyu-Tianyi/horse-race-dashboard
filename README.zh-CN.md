## 关于本分支

RACE EDGE 的经典分析版本：使用 Streamlit 整理香港赛马历史、展示基于历史表现的胜率、比较市场赔率，并按时间验证模型。深色界面以青柠色概率柱和琥珀色市场标记突出逐场研究，强调清晰、紧凑的信息呈现。

当前分支：`main`。两个发布版本共用历史数据、预测方法和验证口径：[`main`](https://github.com/Ruoyu-Tianyi/horse-race-dashboard/tree/main) 为经典分析界面，[`design/hong-kong-neon`](https://github.com/Ruoyu-Tianyi/horse-race-dashboard/tree/design/hong-kong-neon) 为港式霓虹界面。[分支简介 / About](ABOUT.md)

本项目展示按时间独立检验的**历史回放**。它不接入实时赔率，也不执行投注。观察清单用于记录研究对象。

## 第一步：数据集与决策者

**数据集：** [Hong Kong Horse Racing Results 2014–17 Seasons，Lantana Camara，Kaggle](https://www.kaggle.com/datasets/lantanacamara/hong-kong-horse-racing)。

数据集页面注明原始赛果抓取自**香港赛马会（HKJC）**，属于真实历史赛事记录，不是教学合成数据。用户提供的文件与页面的文件名、大小和样本记录相符。页面旧介绍提到 2014–2016 年、1,561 场赛事，最新标题涵盖 2014–2017 年；本项目以实际 CSV 为准，截止日期为 **2017-07-16**。页面列出的许可为 **Unknown**、更新频率为 **Not specified**；采集过程未经独立审计。原始文件哈希保存在 `artifacts/model_report.json`。

| 文件 | 每行含义 | 行数 | 列数 |
|---|---|---:|---:|
| `race-result-horse.csv` | 一匹马在一场比赛中的参赛或赛果记录，包含退赛 | 30,189 | 19 |
| `race-result-race.csv` | 一场比赛 | 2,367 | 12 |

覆盖期间为 **2014-09-14—2017-07-16**，赛场为沙田和跑马地。以 `race_id` 进行多对一合并并验证关联：所有马匹记录均能匹配赛事，没有重复的马匹—赛事组合或重复赛事 ID。

两份原始 CSV 合计约 **8.4 MiB**，单个文件均小于 25 MB。应用主分析读取一份紧凑的衍生文件 `artifacts/predictions.csv`；可选马匹详情使用 `horse_history.csv`。原始文件保留在 `data/`，方便复现，没有随机抽样删减原始记录。预测回放只开放 2017 年独立检验期的赛事。

**目标决策者：** 一位在每场比赛前比较参赛马匹的成年赛马投注研究者。他反复决定哪些马匹值得进一步研究、哪些赛事应当放弃。

## 第二步：为什么采用看板？

1. **谁使用、多久使用一次？** 同一研究者在评估每场赛事时打开看板，决策前再次核对当前参赛阵容与候选马匹；历史验证每周及模型变化后单独复核。
2. **决策句：** 当模型概率与历史市场基准存在明显分歧时，研究者查看马匹此前表现与本场竞争环境，再决定加入观察清单或跳过赛事。正概率差本身不触发投注，也不构成盈利判断。
3. **没有看板时：** 用户需在赛果、马匹历史和赔率表之间切换，手动匹配记录，容易混淆比赛日期、引用过期赔率或忽略历史样本不足。这是拟议工作流与合理推测的成本，数据没有测量节约的时间或金额。
4. **为何不是邮件、报告或提醒？** 每场比赛的参赛阵容不同，赛场、日期、场次筛选与马匹详情能支持重复查询。周报适合模型复盘，难以支持逐场交互；报价过期提醒可作为生产系统补充，但无法替代比较页面。

## 第三步：EDA、信息取舍与页面层级

已执行的 [EDA notebook](notebooks/01_eda_and_validation.ipynb) 使用 **Pandas 和 Matplotlib** 检查数据形状、类型、缺失占位符、关联完整性、赛果代码、距离与月份覆盖、赔率关系和独立验证结果。

### 恰好三个核心指标

三个指标均对应**所选赛事中模型排名第一的马匹**：

| 指标 | 定义 | 展示目的 |
|---|---|---|
| 模型胜率 | 温度校准后，将模型分数在同场参赛马匹之间归一化 | 展示模型首选及其不确定程度 |
| 历史独赢赔率 | 该马在 CSV 中记录的 `win_odds` | 提供价格背景；记录时点及可成交性未知 |
| 模型—市场概率差（百分点） | 模型概率减去同场 `(1/赔率) / sum(1/赔率)` | 寻找值得进一步研究的分歧，**不是**预期收益 |

**辅助图表共两张：** 预测页比较全场马匹的模型概率柱状图与市场概率菱形标记；验证页比较固定模型与历史市场热门马的月度首选命中率。验证摘要是表格，不额外添加一排核心指标。

**筛选与交互：** 赛场、真实比赛日期和场次；历史赛果默认隐藏，可用开关揭晓；选择马匹后查看此前表现。全局验证明确统计全部独立检验赛事，不随单场筛选改变分母。CSV 导出遵守当前场次和赛果揭晓状态。

### 主动省略的内容

1. **原始完赛时间排行榜：** 距离、场地和天气不同，直接混排会把比赛环境误当作能力。
2. **利润、ROI、预期派彩与资金曲线：** 缺乏可成交的赛前报价、完整派彩、费用及时间记录，不能核算实际收益。
3. **完整事故叙述和所有分段位置：** 长文本及结构性缺失的后续赛段会挤占主要比较空间，需要时可查阅原始数据。

### 容易误读的数据及处理方式

- 赛果为字符串，包含退赛、未参赛、未完成和并列名次。已知未完成比赛的有效参赛马匹保留为未获胜；排除退赛、未参赛及未知参赛状态。**六场并列第一赛事**不参与建模与评价，其他并列名次按相同数值保留。
- `NA`、`-`、`---` 和空字符串需显式转换；较短赛事中不存在的后续途中位置属于结构性缺失，不作为预测特征。
- 历史从 2014 年 9 月开始，无法假设拥有马匹完整生涯。首次出现的马匹使用平滑先验。
- 8 月没有观测，首尾月份不完整，不能把覆盖空白解释成表现为零；notebook 展示了覆盖情况。
- 热门马并非与其他马匹等概率获胜，因此必须与历史赔率这一强基准比较。
- 特征只使用比赛日之前的信息，包括骑师与练马师统计；不使用当天及未来赛果。揭晓开关和导出让事后信息的使用保持可见。
- 数据截止 2017 年；标题区说明与侧栏明确标注历史回放，并区分拟议刷新周期和真实数据源。
- 概率是估计值，未提供经验证的不确定性区间；概率差不能解释为确定性等级或保证收益。

## 第四步：刷新频率与行动条件

当前 CSV 是**固定历史快照**，应用不会自动刷新，也没有连接实时投注数据源。以下是取得合适数据许可后的生产设计设想：

- **赛果和历史：** 官方确认赛果后导入，在下一个比赛日前更新历史特征。模型重训单独按周安排，替换前重新进行按时间验证。
- **参赛名单：** 正式赛程发布后导入，并在概率归一化前处理官方退赛变动。
- **赔率：** 赛前每 **60 秒**刷新一次。赔率可能在决策窗口内变化，日度或月度快照不足以支撑价格比较；此频率是设计选择，不是实验求出的最优值。
- **人工查看：** 选赛时查看，决策前复核报价；每周另行检查独立样本表现。数据刷新与人工查看无需同频。
- **行动阈值：** 最新报价超过 **120 秒**未更新，就暂停概率差比较并标记数据质量问题。这相当于错过两次刷新，是拟议服务阈值，不是优化出的投注信号；更近的报价也不保证可以成交。
- **过期成本：** 旧赔率可能改变比较结论；遗漏退赛会改变概率分母；未确认赛果会污染后续特征。过期一天的赔率无法支持逐场决策，一周未更新历史会遗漏近况。

页面说明区保留实际数据期间和拟议刷新周期，区分历史事实与生产设想。

## 模型与独立验证

模型为小型梯度提升分类器。特征包括马匹此前表现、平滑后的骑师与练马师历史胜率、赛场/距离历史、档位、负磅、马重及赛事背景。**本场赔率、赛果、完赛时间和途中位置不进入预测模型。**

- 训练期：**2014-09-14—2016-07-10**，1,557 场符合条件的赛事。
- 校准期：**2016-09-03—2016-12-27**，295 场；概率温度参数仅由此窗口选择。
- 独立检验期：**2017-01-01—2017-07-16**，509 场。
- 固定模型按时间回放；较早检验日已经结束的比赛可以成为后续日期的历史信息，不使用当天或未来结果。

| 方法 | 首选获胜场数 | 首选命中率 | 前三顺位覆盖冠军 | 每场对数损失 ↓ |
|---|---:|---:|---:|---:|
| 历史表现模型 | 128 / 509 | 25.1% | 55.0% | 2.202 |
| 历史赔率热门马 | 148 / 509 | 29.1% | 63.3% | 1.991 |

结果**不支持模型优于市场的说法**。“前三顺位覆盖冠军”指实际冠军出现在预测前三之中，不是位置投注命中率。概率或赔率相同时，用 `horse_id` 确定顺序。本看板不计算利润。

## 第五步：运行与部署

项目使用 **`uv init`** 初始化，在 **Python 3.14** 下验证。应用读取已提交的预测文件，启动时无需重新训练。

```powershell
uv sync --group dev
uv run streamlit run app.py
```

重新生成模型结果、已执行 notebook 并进行核心检查：

```powershell
uv run python racing_model.py
uv run python create_notebook.py
uv run python verify.py
```

notebook 生成器使用项目内 Jupyter 内核并保存执行输出。`uv.lock` 固定解析后的环境，`requirements.txt` 支持仅安装应用运行依赖。
